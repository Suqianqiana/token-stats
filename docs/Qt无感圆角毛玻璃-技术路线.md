# Qt 实现「无感圆角毛玻璃」界面的技术路线

> 项目：Token 统计卡片（PySide6 / Windows）
> 完成时间：2026-10-20（第 84~94 轮）
> 目标效果：面板背景是**系统实时模糊**（真毛玻璃），圆角与外框干净，
> 与"默认 / 液态玻璃 / 静态背景"三种模式的布局口径完全一致。

---

## 0. 一句话结论

**Windows 的 DWM 亚克力材质只能铺满"窗口矩形"，无法只作用于某个区域；
因此想让"面板是模糊的、面板外一圈是桌面"，唯一的办法是——
把材质挂在另一个**尺寸恰好等于面板**的底层窗口上（双层窗口）。**

---

## 1. 需求拆解

| 要求 | 含义 |
|---|---|
| 真·实时模糊 | 必须是 DWM 合成的模糊（背景变化会实时跟着变），不是截图糊化 |
| 圆角干净 | 面板的圆角外侧不能出现方形材质角 |
| 无多余外框 | 窗口最外层不能出现任何原生边框 / 辉光 |
| 不割裂 | 面板尺寸、外边距必须和其它三种模式一致（外圈 10px 透出桌面） |

---

## 2. Windows 相关 API 实测结论（全部在本机实测，非文档推测）

| API | 作用 | 实测结果 |
|---|---|---|
| `SetWindowCompositionAttribute` + `ACCENT_ENABLE_ACRYLICBLURBEHIND` | 亚克力材质 | ✅ **唯一能提供真·实时模糊**；但**铺满整个窗口矩形** |
| `DwmEnableBlurBehindWindow` + `hRgnBlur` | 区域模糊 | ❌ Win10/11 上**完全不模糊**（窗口纯透明，能看清背后网页） |
| `SetWindowRgn`（原生）/ `QWidget.setMask()` | 裁剪窗口形状 | ❌ **只裁 Qt 自己的绘制**，DWM 材质照样铺满矩形 |
| `DWMWA_SYSTEMBACKDROP_TYPE=3`(Acrylic) / `=4`(TransientWindow) | 系统 backdrop | ❌ 同样只能铺满矩形 |
| `DwmExtendFrameIntoClientArea(-1,-1,-1,-1)`（即 `add_shadow()`） | 扩展边框 | ⚠️ 会在最外圈画出**原生实线边框**，且切模式后不会自动消失 |
| `DWMWA_WINDOW_CORNER_PREFERENCE`（即 `set_corner()`） | 系统圆角 | ⚠️ 能把窗口裁成圆角，但会带出**外扩的边框/辉光**；用在主窗口 → 外框复现；用在背板 → 正好提供圆角 |
| `Qt.NoDropShadowWindowHint` / `DWMWA_NCRP_DISABLED` | 去投影 | ❌ 都拦不住上面那条外扩边框 |

**关键实验**：同一背景（高对比 2px 竖条纹）、同一位置、三方案并列截图 ——
A 不裁 / B Qt `setMask` / C 原生 `SetWindowRgn` —— 外圈的材质**全都还在**。

## 3. 核心矛盾与取舍（二维扫描数据）

面板是 14px（现为 10px）圆角，背板是矩形：

- 背板**内缩** → 直边出现"未模糊带"（背板没盖到的地方露出未模糊桌面）
- 背板**不内缩** → 背板的直角在圆角"缺口"处露出材质

实测（带面板、条纹背景、含"边缘清晰带 = 面板直边内侧亮度标准差"）：

| 配置 | 未模糊带（低=好） | 外圈（低=好） | 角尖材质（低=好） |
|---|---|---|---|
| 内缩 6 + 无系统圆角 | 39.5 ✗ | 0.2 ✓ | 1.4 ✓ |
| 内缩 0 + 无系统圆角 | 0.5 ✓ | 2.4 ✓ | 86~96 ✗ |
| **内缩 0 + 系统圆角（选定）** | 15 ✓ | 4.3 ✓ | 15.5 |

→ 单一矩形窗口**无法同时满足**；于是有了下面的架构。

## 4. 最终架构：双层窗口

```
        ┌───────────────────────────────┐
        │  主窗口 (CardWindow)           │  ← 990×610，margins 恒 10px，无 DWM 材质
        │  ┌─────────────────────────┐  │     只画罩层 + 内容与圆角面板
        │  │ 面板区域 970×590         │  │
        │  │                         │  │
        │  └─────────────────────────┘  │
        └───────────────────────────────┘
                    ▲ 在其正下方（z 序更低）
        ┌─────────────────────────┐
        │ 背板窗口 frost_backdrop  │  ← 970×590，**Acrylic + 系统圆角**
        └─────────────────────────┘
```

要点：
- 背板尺寸 = 面板矩形（`INSET = 10`，即主窗口内缩 10px 后的矩形），**不再额外内缩**
  → 模糊一直铺到面板边缘，没有未模糊带；
- 背板的圆角由 `set_corner(2)` 提供 → 背板自己是圆的，不会往圆角缺口溢出方形材质角；
- 主窗口那 10px 外圈不属于任何带材质的窗口 → **露出真实桌面**；
- 定位必须用 `geometry()`（无边框窗口上 `frameGeometry()` 语义不稳，会造成整体偏移）。

### 生命周期同步

| 事件 | 处理 |
|---|---|
| `showEvent` | 创建/复用背板 → 对齐 → 挂材质 → `fw.lower()` → 主窗 `raise_()` |
| `moveEvent` / `resizeEvent` | 重新对齐背板矩形 |
| `hideEvent` / 最小化 | 背板一起 hide（否则屏幕上会剩一块"玻璃板"） |
| 切走材质 | 撤材质 + `reset_frame()` + `reset_corner()` + 隐藏 |

## 5. 圆角对齐：让两个圆重合

`set_corner(2)`（ROUND）的实际半径由 Windows 按 DPI 决定，**调不了**
（该 API 只有枚举：不圆 / 圆 / 小圆 / 默认）。

但**反过来可以对齐**：5x 放大截背板角部，量出系统圆角实际约 **10~11 逻辑 px**，
于是把主面板圆角从 14 改成 **10**（`_PANEL_RADIUS = 10`，所有模式统一），
两层圆角基本重合 → 圆角缺口处的月牙消失。

## 6. 状态机：挂 / 撤材质的判据与次序

### 判据

```python
_will_want = new_frost and not new_static      # 静态背景虽属毛玻璃系，但不用亚克力
```

⚠️ 曾经写成 `new_frost`，导致"毛玻璃→静态背景"被误判为"不需要撤材质"而走了错误分支。

### 撤材质的正确次序（避免闪帧）

```python
ACRYLIC["on"] = False        # ① 先让绘制代码切到"新样式的实底"
self.repaint()               # ② 同步绘制（新样式已盖住背板材质）
self.card.repaint()
self._sync_acrylic(force=True)   # ③ 再撤材质（此时它已被挡住，看不见）
```

⚠️ 曾经的两种错误写法：
- 立即撤 → 背板没了、新底图还没画 → **闪一下全透**
- 延迟 130ms 撤 → 新样式先画在材质之上 → **先发闷再正常**
- "先 `repaint()` 再撤"但 `ACRYLIC["on"]` 仍为 True → 画的还是透明罩层 → **照样闪**

## 7. 明暗切换同步

最终次序（实测最优）：

```
refresh_palette() → 刷纹理缓存 → apply_styles → apply_app_qss
  → 刷新子页主题 → _update_all() → 【最后】下发 DWM tint
```

⚠️ 试过"先发 tint + `repaint()`"，实测**更不同步**：tint 一发 DWM 立即变色，
而样式重刷要几十毫秒，反而拉长了不同步的时间窗口。

## 8. 浅色模式的可读性

浅色主题里 `TEXT3=(150,158,172)` 是为**不透明白底(246,248,251)** 设计的。
浅色毛玻璃的面板是半透明的（模糊背板 + 白 tint 48% + 罩层），灰字会融进背景。

修法（`refresh_palette()` 内，仅浅色 + 毛玻璃时覆盖）：

```python
if theme_state.get("frost") and not theme_state["dark"]:
    globals().update(TEXT2=QColor(64, 72, 88), TEXT3=QColor(96, 104, 120))
```

## 9. 核验方法：像素差分（客观判据）

工具：`tools/verify_frost_corners.py`

1. 铺一张**高对比 2px 竖条纹**假桌面（模糊→均匀灰，清晰→黑白分明）；
2. 先截一张"无应用"的参考图；
3. 把主窗口以指定材质放到固定位置，再截一张；
4. 对三类敏感区域逐像素求**平均绝对差**：
   - 外圈 10px 环带（四条直边中段）—— 当初"矩形外框"就该在这里被抓出来
   - 四角圆角缺口（面板圆角外的直角区）
   - 面板内中心（**对照项**：这里应该有**大差值**，证明模糊确实生效）

判读：环带/缺口 ≈ 0 → 露出真实桌面（正确）；差值大 → 材质残留。

> 这套判据的价值：它把"看起来还行"变成"测出来是多少"。
> 本项目第 82~85 轮连续几轮都靠肉眼看截图下结论，结果漏检了外框，被浅猫纠正。

⚠️ 两个大坑：
- 条纹**不能**用 Qt 样式表的 `repeating-linear-gradient`（那是 CSS3 语法，Qt 不支持），
  必须用 `QPainter` 画，否则背景是纯色，对照项永远测不出来；
- 取样坐标必须用 `geometry()`，`frameGeometry()` 会整体偏移。

## 10. 踩坑清单（经验沉淀）

| # | 坑 | 教训 |
|---|---|---|
| 1 | `QImage(Format_Mono)` + `QBitmap.fromImage` 做 mask | Mono 的色彩表**索引 0 默认是白色=不透明**，`fill(0)` 等于全不透明 → 整窗遮死、点不动。改用 `QRegion(path.toFillPolygon().toPolygon())` |
| 2 | `GradientColor` 字节序 | DWM 要的是 **AABBGGRR**（只把 R/B 对调），不是整串倒置。写错会导致浅色变"不透明青色"、暗色变"暗红" |
| 3 | 行号循环删代码块 | 曾一次删掉几百行，文件从 7992 行掉到 6402 行。多行改动只用 Edit 工具 |
| 4 | `env VAR=.. python` | 本机 bash 下**输出会丢失**（"回归通过"其实是空跑）。改用 `export` |
| 5 | 截图肉眼下结论 | 漏检外框。改用像素差分核验器 |
| 6 | demo 与主程序口径不同 | demo 没有"外圈"，导致投票选定的方案在主程序上复现外框。**demo 结论必须回主程序复核** |
| 7 | `scan_full(force=True)` | 现在要 69 秒，回归总时长 >10 分钟 → 跑回归用后台 |

## 12. 已知限制

- **系统圆角半径不可调**（Windows 决定），只能由我们的面板半径去迁就；
  跨 DPI 时系统圆角会变，若要完美可考虑按 DPI 动态取 `_PANEL_RADIUS`。
- Win11 的 `set_corner` 在背板边缘会带一条**极细的原生描边**（在圆角处最明显），
  目前观感可接受；若将来要彻底消除，需要放弃系统圆角、改用其它圆角来源。
- 浅色毛玻璃的可读性依赖"加深灰字"的补偿，若用户桌面极亮，仍可继续微调 `TEXT2/TEXT3`。
